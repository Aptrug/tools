## Must fix
**1. Bonus: off-by-one in the fd bound check (`get_next_line_bonus.c`).**
```c
if (fd < 0 || fd > MAX_FILED || BUFFER_SIZE <= 0)   // fd == 1024 passes
```
`fs` has `MAX_FILED` entries, so `fd == MAX_FILED` writes one slot past the array. ASan confirmed it: `global-buffer-overflow ... WRITE of size 4`. Your own README says "strictly smaller than `MAX_FILED`", so the code contradicts it. A crash is an automatic 0, and a reviewer will spot this by reading. Change `>` to `>=`.

## Strongly recommended
**Quadratic slowdown on long lines.** Every read re-measures the line with a byte-by-byte `ft_blksize` and copies it again in `ft_memjoin`. Timings I measured:

| Input | `BUFFER_SIZE` | Time |
|---|---|---|
| 1M-char single line | 42 | **~25 s** |
| 100k-char line | 1 | ~13.6 s |
| 100k normal lines (5 MB) | 1 | 1.8 s |

Normal files are fine. But evaluators like "huge line + small buffer" tests, and a timeout there fails you. The usual fix is to stop re-joining on every read: find the line length first, or grow the line in chunks.

**The `ft_memset` block at the end of `get_next_line` is a hack.** After you consume a buffer exactly, you zero it but leave `bytes` unchanged. The next call then joins `bytes` zero bytes onto the line and relies on `strlen` to ignore them. With `BUFFER_SIZE=10000000` that is a 10 MB memset and a 10 MB copy for nothing. Setting `f.bytes = 0` instead (`fs[fd].bytes = 0` in the bonus) does the same job. I applied that and the bound fix on a copy and re-ran everything, including the multi-fd test and `fd == 1024`. It all passed, and `fd = 1024` now returns NULL.

## Smaller notes
- **Naming:** `do_crazy_stuff` and `read_more_stuff` will read badly to peers and recruiters, who are explicitly the README's audience. I'd rename them.
- **Read errors:** if `read()` fails mid-line, you return the partial line instead of `NULL`. The subject says `NULL` on error. This is an edge case.
- **Dead code:** `ft_memblk` is unused. The `void *` arithmetic is a GNU extension, so it compiles fine with your flags but warns under `-Wpedantic`.
- **Mandatory static state:** it holds a single fd's state. That's allowed, and your README documents it, but expect to be asked about it in defense.
